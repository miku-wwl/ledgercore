# LedgerCore V2 textbook — sources and build

《企业级银行交易系统：Java 全栈、金融一致性与可靠性工程实战》
(LedgerCore V2 — 企业工资支付、异步清算、故障恢复与生产式验证)

The book is generated only from committed sources and from the frozen application commit named in `metadata.yaml`
(`source-sha`, the E12 source freeze in `docs/v2/E12-SOURCE-FREEZE.md`). The V1 textbook under `manual/` (other than
`manual/v2/` and the new PDF in `manual/dist/`) is unchanged.

| Path | Content |
|---|---|
| `metadata.yaml` | Title, frozen `source-sha`, cover text and counts |
| `chapters/*.md` | Preface, 26 chapters, appendices A–I (pandoc Markdown; appendix I is generated by `tools/gen_e12_catalogue.py` from `assessment/e12/cases.json` and `evidence/round4/e12/E12-RESULTS.json`) |
| `diagrams/*.svg` | All figures, generated by `tools/make_diagrams.py` (mechanism diagrams and evidence-driven data figures) |
| `figures/screenshots/` | Genuine screenshots captured from the frozen build by `tools/capture-incident.ps1`, with `capture-manifest.json` |
| `assets/` | HTML template, stylesheet and render script |
| `tools/` | `build.py` (preprocess, pandoc, Edge print), `make_diagrams.py` + `figs_*.py`, `qa_pdf.py`, `pdf2png.py`, `contact_sheet.py`, `svg_preview.py`, capture scripts, `requirements.txt` |
| `PUBLICATION-MANIFEST.md` | What was built, from which sources, with which checks |

## Build

From the repository root, with pandoc 3.8, Microsoft Edge and a Python with `tools/requirements.txt`:

```powershell
python manual/v2/tools/make_diagrams.py
python manual/v2/tools/build.py
python manual/v2/tools/qa_pdf.py manual/dist/LedgerCore-V2-Enterprise-Banking-Reliability-Engineering.pdf
python manual/v2/tools/contact_sheet.py manual/dist/LedgerCore-V2-Enterprise-Banking-Reliability-Engineering.pdf work/book-v2/sheets
```

`build.py` reads every code excerpt with `git show <source-sha>:<path>` (`@@excerpt` directives in the chapters), so the
book cannot quote code that differs from the frozen commit; each excerpt links to the GitHub blob at that commit. Figures,
tables and excerpts are numbered per chapter and every `@fig-…`, `@tbl-…` and `@code-…` reference must resolve. Data
figures read their numbers from `evidence/` at generation time and fail if a file is missing. Build scratch goes to the
ignored `work/book-v2/`. Fonts are the installed Microsoft YaHei and Cascadia Mono, embedded by the PDF printer; no font
file is stored in the repository.

## Screenshots

`tools/capture-incident.ps1` (Windows PowerShell) reuses the E6 lab guards: a disposable PostgreSQL cluster on
`127.0.0.1:55437`, the bank and simulator JARs built from the frozen source, a Vite dev server on `127.0.0.1:5173`, and
synthetic `example.test` users. It creates a genuine reserve shortage with the guarded lab command, captures the
Operations console and Payments page, then replenishes, retries once (governed) and captures again. Credentials exist
only in the ignored run directory; `capture-manifest.json` records the run, the JAR SHA-256 values and each file's
SHA-256. Older genuine screenshots are referenced in place: `manual/assets/screenshots/` (V1, commit `484b9ad`) and
`evidence/round3/e11/screenshots/` (E11, commit `fdd4e0d`).

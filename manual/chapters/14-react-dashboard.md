# 第 14 章　React 仪表盘的状态边界

React 页面呈现当前客户、账户列表、余额、历史和转账结果。这些值来自不同地方：账户和历史是服务端状态；金额与账户选择是用户输入；成功回执是一次用例结果；未知网络结果是还需核实的用户意图。将它们统统当作一个全局对象，会让缓存更新和业务恢复边界变模糊。

![组件、本地状态与 API 边界](manual/figures/14-react-state.svg)

App 路由包含登录、总览、账户详情、转账与历史页面。BankLayout 承担导航；TransactionsList 展示活动列表；页面通过带 OpenAPI 生成类型的 API client 调用服务端。金额助手使用 BigInt 解析分币，不在余额求和时引入 JavaScript 浮点误差。

![真实页面：完成转账后的桌面仪表盘](manual/assets/screenshots/dashboard-desktop.png)

![真实页面：390 像素移动视口](manual/assets/screenshots/dashboard-mobile.png)

截图中的总余额为 NZ$2,000.00，账户分布为 Everyday NZ$942.00 与 Savings NZ$1,058.00。这是隔离数据库中测试用户实际开户、转账后观察到的数据，不是页面硬编码常数。移动视口检查 document 宽度没有超过 390 像素，导航切换为底部操作栏。

界面状态能帮助用户理解服务端结果，但不能保护账本。用户点两次、标签页挂起或刷新，都可能改变请求和响应顺序；权限、幂等和原子性仍必须由服务端实现。React 的状态更新不是数据库事务。

**观察题：** 小屏幕布局应该优先保留哪些操作？除了按钮可见性，还需要测量什么？一个稳定的界面检查至少包含实际视口尺寸、横向滚动宽度与关键状态的可访问标签。

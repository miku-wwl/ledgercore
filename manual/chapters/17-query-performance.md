# 第 17 章　PostgreSQL 查询与索引取舍

先描述查询形状，再讨论索引。账户历史以账户 ID 过滤、按创建时间与转账 UUID 倒序排序并按游标截取；余额读取按 Posting 账本账户聚合；幂等预留依赖客户、操作、键组成的唯一索引。迁移 V1–V4 为这些读写路径创建索引和约束。

![过滤、排序和 LIMIT 如何共同影响计划](manual/figures/17-query-index.svg)

LedgerCore 的性能实验在独立 PostgreSQL 18.7 数据库中装载合成数据：1,000 个客户、10,000 个账户、60,000 个凭证、120,000 条分录、50,000 笔转账。账本和余额投影差异为 0，提交约束通过。脚本严格要求数据库名为 ledgercore_perf，移除索引比较结束后会恢复原索引。

在原实验中，交易历史查询使用付款方和收款方两个索引，计划采用 BitmapOr 后读取匹配项，再连接账户名称、排序并限制到一页。去掉这组索引后，计划改为扫描 50,000 笔转账；一次本机实验的时间和共享缓冲访问同时上升。这个差异说明被测工作负载受索引帮助，不说明对所有分布都应该复制同一索引。

索引加快读取，却增加写入、空间、统计维护与迁移成本。应使用 PostgreSQL 18 的 EXPLAIN (ANALYZE, BUFFERS) 检查实际计划、行数估计和 buffer 数量，并用生产代表性数据反复测量。本实验是单机、合成、单用户 SQL，不测并发吞吐、尾延迟或故障切换。EXPLAIN 的解释见参考资料中的 PostgreSQL 官方文档。

**安全提示：** 移除索引实验只可在一次性数据库运行。检查脚本的数据库保护条件，确认清理脚本确实恢复迁移定义的索引，再把结果写进性能说明。

# 第 2 章　用复式记账保存守恒关系

如果只把账户余额减 25、加 25，如何证明这两步总是一起发生？一个更新成功、另一个失败时，钱就凭空消失或出现。复式记账把一次经济事件表示为同一币种的多个分录；本例对付款账户记借方 25.00，对收款账户记贷方 25.00。借贷总额必须相等。

在 LedgerCore 的客户存款账户中，余额按贷方正常方向理解。转出会对付款方的负债账户记借方，转入会对收款方记贷方。这里的“借”并不等于日常语言中的借钱；它是账户分类与正常余额方向的一部分。开户模拟资金还对应系统模拟储备账户的一笔反方向分录，因此系统不会把一笔孤立的客户余额伪装成完整账务。

![借贷分录如何保持金额守恒](manual/figures/02-debit-credit.svg)

账本记录的是发生过什么，而投影记录的是为了快速查询而计算出的当前余额。每个账本账户只有一条分录时，合计借方与贷方也必须相等；改变业务结果要新增冲正凭证，而不是把过去那行改掉。金额以整数分币存储，HTTP 输入使用两位小数的十进制字符串。

模型在 Java 构造期间检查至少两条分录、账户不重复、借贷总额相等。PostgreSQL 还会在事务提交时复查数据库中的分录集合。两道检查解决不同问题：Java 反馈领域错误；数据库防止其他 SQL 写入路径绕开 Java 不变量。

**一个边界问题：** 借贷平衡能保证经济上正确吗？不能。它能检查结构守恒，却无法判断收款人是否正确、授权是否充分、用户是否误输金额。因此还需要身份、所有权和用户确认等约束。

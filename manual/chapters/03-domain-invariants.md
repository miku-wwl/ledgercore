# 第 3 章　把不变量放进领域模型

转账规则若只散落在控制器、SQL 和页面提示中，任何新入口都可能漏掉其中一条。领域模型把有业务含义的值和不变量放在能够拒绝非法状态的位置。Money 不是 double；JournalEntry 不是任意 List；TransferService 不是通用 SQL 容器，而是这个用例的事务协调者。

账户、账本账户、凭证、分录和转账各有身份。账户表示客户使用的银行产品；账本账户表达复式记账中的会计一侧；凭证把相关分录组合为同一事件。项目里客户账户状态由账户领域模型表达，而余额和 Posting 由账本模块管理。这样的分离使“暂时停用账户”不需要篡改历史凭证。

![领域不变量所在位置](manual/figures/03-invariants.svg)

代码把金额限制为正的最小单位，把反转限制为一次，并且拒绝反转凭证再次反转。它没有试图把整个系统都包装进一个巨型 Aggregate；数据库事务负责跨账本账户协调，行锁保护竞争条件，提交触发器保护落库后的完整性。DDD 不要求一切都变成对象图。

领域建模的实际判断题是：这条规则如果被违反，会损坏哪个业务事实？“只允许正金额”属于金额值和用例输入；“不能透支”需要基于当前账本余额并与并发写入协调；“请求来自本人”需要认证上下文。这些规则相互关联，却不应假装由同一个类完成。

**反例。** 如果把余额作为 Money 字段放在 Account 对象上，再用内存中的 setter 扣款，两个同时加载的对象都可能看到 100.00，并各自接受 80.00。领域对象的局部正确性不能代替并发控制。

**复习问题：** 哪些不变量可以在构造器里验证？哪些必须等数据库并发语义参与后才能成立？把“借贷相等”与“不会超额支出”分别定位。

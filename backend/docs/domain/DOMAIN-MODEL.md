# LedgerCore 领域模型

P2 实现 `Money`、`LedgerAccount`、`JournalEntry`、`Posting`、客户账户生命周期、固定开户模拟资金、模拟入金、余额投影重算与整笔冲正。P3 增加 `TransferService`、双边转账凭证、`Transfer` 与成功幂等回执，并以 PostgreSQL V3/V4 约束事务与重放。交易历史、对账结果、身份认证及所有业务 HTTP 路由仍待后续阶段；当前转账服务没有公开 HTTP 入口。

## 账务约定

每个 Posting 表示一条正数、单币种金额及其借方或贷方。借贷是复式会计记账方向，不是界面上的“转入/转出”同义词。

账户类型决定正常余额方向。资产通常借方增加；负债通常贷方增加。客户存款在银行账务中是银行对客户的负债，所以贷记该账户增加客户余额，借记该账户减少客户余额。客户看到的余额是该负债账户的贷方正常余额；转账页面的“转出”对应其借方 Posting。

所有账务金额以分表示。API 接受和返回规范的 NZD 十进制字符串，例如 120.00；Java 在边界用精确转换解析，领域中用 long，PostgreSQL 用 BIGINT。浏览器用十进制字符串和 BigInt 处理金额，不把金额转为二进制浮点数。单条 Posting 金额必须大于零，零和负金额在命令入口拒绝；加总与换算使用溢出检测。

## 实体与所有权

| 概念 | 职责和关键字段 |
|---|---|
| Customer | 已认证客户的内部 UUID、规范化唯一邮箱、密码哈希和创建时间。会话身份映射到 Customer；请求体不能指定身份。 |
| Account | 面向客户的 NZD 模拟账户：UUID、ownerCustomerId、显示名称、状态、创建和关闭时间。只能由所属客户访问。关闭不删除历史。 |
| LedgerAccount | 会计账本账户，记录账户类别、正常余额方向、是否为系统账户，以及可选的客户 Account 关联。每个客户 Account 对应一个客户存款负债 LedgerAccount。 |
| JournalEntry | 一项不可变会计事实：UUID、类型、业务时间、币种、来源引用，以及可选的被冲正凭证。成功后不能编辑或删除。 |
| Posting | JournalEntry 中的一条记账行：LedgerAccount、DEBIT/CREDIT、正的 amountMinor 和 NZD。分录行不独立于凭证提交。 |
| Transfer | 已成功内部转账的业务记录，关联付款账户、收款账户、发起客户、金额、账务凭证和提交时间。未提交的尝试不伪装成成功 Transfer。 |
| IdempotencyRecord | 以已认证客户、操作类型和 Idempotency-Key 唯一定位；保存规范化请求指纹、成功 Transfer 和稳定回执。只在资金移动提交时一同提交。 |
| AccountBalance | LedgerAccount 的可重建余额投影，用于读取，不是可任意修改的会计事实。分录提交时同事务更新；借方正常余额按借方减贷方，贷方正常余额按贷方减借方。 |
| ReconciliationResult | 只读比较某次账本聚合余额与投影余额的结果：账户、币种、账本金额、投影金额、差值、检查时间和结果。差异须可定位；对账不偷偷修改历史。 |

## 资金如何进入账本

开户赠送 NZD 1,000.00 时，系统建立一张 OPENING_FUNDING 凭证：

| 账务账户 | 借方 | 贷方 | 含义 |
|---|---:|---:|---|
| Simulation Reserve（模拟储备资产） | 1,000.00 | — | 记录模拟资金的明确来源 |
| 客户存款负债（客户新账户） | — | 1,000.00 | 银行对客户的模拟存款负债增加 |
| 合计 | 1,000.00 | 1,000.00 | 凭证平衡 |

Simulation Reserve 是教学用的虚拟资产账户，不表示真实现金或央行储备。不能通过直接修改客户余额来创建初始资金。

## 转账如何记账

Alice 从存款账户向 Bob 转 NZD 120.00。单张 TRANSFER 凭证有两条 Posting：

| 账务账户 | 借方 | 贷方 | 客户可见变化 |
|---|---:|---:|---:|
| Alice 的客户存款负债 | 120.00 | — | Alice 减少 120.00 |
| Bob 的客户存款负债 | — | 120.00 | Bob 增加 120.00 |
| 合计 | 120.00 | 120.00 | 资金守恒 |

这两条 Posting 属于同一凭证、同一数据库事务。源账户可用余额来自该客户负债账本的净贷方余额；扣款前不得信任仅由客户端或缓存提供的数字。

## 拒绝、回滚与冲正

金额无效、权限不足、账户关闭或余额不足时，转账命令不产生成功 Transfer、Posting、余额变化或成功回执。数据库事务中途失败时全部回滚。客户端只在明确收到成功回执时显示“成功”；连接中断视为结果未知，使用原操作意图和原 Idempotency-Key 再确认。

已提交交易不能删除或改金额。错误通过新的 REVERSAL 凭证纠正，保留原凭证引用并交换原 Posting 的借贷方向；原交易和冲正都可审计。MVP 采用整笔冲正，部分冲正待单独业务决策。如果冲正会使某个客户存款负债出现负的贷方余额，MVP 拒绝自动冲正并明确报告资金恢复所需操作；不会为了更正历史而隐式放宽 INV-03。客户应收款和追回流程不属于 MVP。
